# 全股票资料库

股票范围直接来自本地 `security` 表中的沪深北A股，不受任何一次选股任务影响。新增证券入库后自动出现在清单中；可按代码、名称、行业、资料状态查询，每页50只。

点击代码或名称进入已有个股详情，返回时保留资料库的查询和页码；多策略选股入口仍返回原选股结果。

## 采集方式

首次进入资料库自动提交全A股采集任务。进入页面时会检查新增股票与超过7天需要核对的资料：上次任务完成满一天且有待处理项时按需提交下一批。暂停的任务不自动恢复，使用“继续采集”。“补齐 / 核对经营评述”可手动提交；已有活动任务直接复用。“重试失败股票”只处理失败标记的股票。

当前批量只抓公开 `operate.html` 中的主营介绍和经营评述，复用已有解析、原文版本存储与报告期切换。公司资料与高管履历仍可在个股详情中按需更新。

每个股票的报告按网页提供的期数入库；未提供全文明确标记“来源暂无全文”，不视为成功补齐。页面入库数量为具备全文的股票和报告期数，修订版本不会重复计数。

7天内的已有全文直接复用；重新核对发现内容未变时，只更新任务核对时间，不制造重复原文版本。“来源暂无全文”也保留7天检查间隔。失败保留旧报告，可以单独重试。资料长期留存，历史修订不覆盖。

## 后台与恢复

`company_collection_job` 保存全量任务、暂停请求和心跳，`company_collection_item` 逐股保存状态、尝试次数、期数与错误。后台是独立Python进程，3个下载线程，请求起始间隔至少1.5秒；每只股票完成即提交数据库，关闭网页不影响采集。全量任务和逐股手动更新不依赖技术选股进程。

运行中的网页任务显示进度、复用数量、新保存数量、来源无正文和失败数量。支持暂停与继续；暂停等待当前请求处理完成。任务心跳超过2分钟未更新，显示中断可继续。恢复后重置未完成项，已成功入库项保留。连续5次403、429或证券验证失败时停止派发并暂停，避免持续访问受限来源。

一个全量后台进程由PostgreSQL会话锁约束，预约任务另用事务锁避免重复创建。测试使用独立数据库schema和独立锁，避免影响正式采集。

## 接口

- `GET /api/stock-library?q=&industry=&state=&offset=0&limit=50`
- `GET /api/stock-library/job`
- `POST /api/stock-library/jobs`：`{"mode":"due"}` 或 `{"mode":"retry"}`
- `POST /api/stock-library/jobs/{id}/pause`
- `POST /api/stock-library/jobs/{id}/resume`

后台日志存放 `.runtime/company-library-{id}.log`。可通过 `python -m quant.company_library_worker 任务ID` 运行已预约的任务，网页负责通常的提交和继续操作。

来源同一报告期出现多份不同正文时，在同一报告期条目中保留全部原文，并明确标注未判断版本先后；完全相同的重复正文不重复展示。原始网页仍按版本保存。
