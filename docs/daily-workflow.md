# 每日盘后选股

## 日常操作

1. 在通达信完成A股盘后数据下载。
2. 打开“多策略选股”，确认折叠设置中显示的股票范围和策略数量。
3. 点击“开始选股”。系统依次检查日期和文件变化、同步日线与权息、更新已下载股本财务、运行策略、保存归档。
4. 查看结果。“已完成并归档”表示整条流程结束；有失败项时可单独补算。零信号也归档。

“更新行情”只同步行情，不运行策略。关闭网页不停止后台任务；关闭服务或关机会中断，重新启动后可检查状态并继续。用户主动停止的任务不会自行恢复。

七个策略源码及默认参数不变，日线前复权、全历史、量单位手和原周月聚合规则不变。

## 日期与完整性

不能仅以文件修改时间、单只股票或数据库最大日期判断全市场已更新。

- 源文件最高交易日必须满足既有80%有效源文件覆盖门槛，不能退回旧日期冒充最新。
- 有已核验交易日历时，新选股必须使用截至当前盘后时点应有的最近交易日；工作日漏下载会阻断，不重算昨天。
- 收盘数据就绪时点仍为北京时间15:45；周末与休市日使用最近已结束交易日。
- 内置2026年日历，依据[上交所2026年休市安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)。未知年份不猜节假日，页面明确提示日历未核验；仍检查本地最高日期与覆盖。新年度需补充完整日历。
- 缺源文件、较旧文件、未到目标日期的数量分别保留；缺失不填零，也不将其自动称为停牌。该覆盖门槛不等于已核实每只股票都完整。
- 正在写入会有限重试；仍不稳定、截断、导入错误、源文件回退或同步后再次变化时，不启动策略。
- 快速检查使用大小、修改时间及尾部指纹；保留时间戳的深层历史修订需使用数据总览中的完整哈希校验。

已下载财务及股本按既有导入规则接入，缺财报不阻断技术扫描，冲突报告仍隔离。财务资料更新问题保存在准备任务的auxiliary信息，不替用户挑选冲突值。

## 重复运行与恢复

输入标识包含交易日、股票范围及实际清单、策略代码与参数、行情版本和历史股本依据；并行数不影响结果身份，财务附加值不影响技术身份。

- 相同数据与方案已有归档：打开旧结果，不重复技术扫描。
- 相同方案运行中：进入当前任务。
- 行情、权息、范围或策略变化：新建版本，旧结果保留。
- “重新计算并保留新版本”可明确强制重算。
- 继续前检查输入版本和股票清单。默认最新任务通过网页继续时，还要检查本地资料是否已变化；变化后需新建任务。
- 失败项重试创建关联的新版本，只复用无错误股票，失败股票重新执行，原尝试和归档不改写。
- 行情导入使用排他锁，技术扫描使用共享锁；网页、API、MCP和CLI执行同一批导入/选股函数，防止扫描中改写行情与权息。
- 状态查询及启动会识别无主运行任务；新排队任务保留120秒派发宽限，不会永久假运行。
- 页面短暂断线自动重连，刷新后从持久化任务恢复。准备、扫描及归档进度分开保存，页面显示总进度。

## 当次归档和最新财务

默认结果表继续按用户要求附加最新财务，明确价格日期、财报期与参考日。

“当次归档”保存该次完成时的技术信号、财务值、来源、参数、输入清单、状态及错误。后续财报更新不改变归档。停止后再继续同一任务，会保留不同归档修订R1、R2；失败项补算则是关联的新任务版本V2等。

旧任务缺少当次财务快照时标明旧记录，不用今天的财务补造过去。旧任务仍可查看最新财务或导出当前视图。

归档保存在screen_archive；主任务和逐股记录仍在multi_screen_run/multi_screen_item。查询最新财务不会改写原技术信号。

每次归档默认在`.runtime/archives/交易日/任务ID-r修订号.json`保存本地副本，可用QUANT_ARCHIVE_DIR指定目录。JSON带数据SHA256。副本失败不撤销数据库归档，页面可重试。

输入清单与指纹用于变更检查，不等于完整的历史行情快照。没有保存所有被修订原始行情时，不能承诺未来逐点重算或首次披露版回测。

历史结果支持交易日、方案、状态及分页。与上次同方案完整归档比较新增、持续、消失股票；不是默认与相邻交易日比较，部分失败不生成可靠对比。

“导出全部结果”为原始数值CSV，“导出当前筛选”为当前排序与格式化展示CSV，“下载归档JSON”为选定修订的完整归档。CSV做公式文本转义。零信号导出保留表头，JSON保留完整任务状态。

## 数据库备份

归档JSON不是全库备份。单独备份命令：

```powershell
.\.venv\Scripts\python.exe -m quant.cli backup-db
```

默认使用`.runtime/pgsql/bin/pg_dump.exe`，输出自定义格式dump到`.runtime/backups/`；可设置QUANT_PG_DUMP及QUANT_BACKUP_DIR。密码仅经子进程环境变量传递，不写命令行或文档。

默认不在每次选股后复制数GB数据库。若需要每次归档后全库备份，可显式设置QUANT_BACKUP_ON_ARCHIVE=1。失败保留既有结果并显示问题，不覆盖已有备份。

恢复须在另一个空数据库先验证，使用与服务端兼容的pg_restore；本次升级不覆盖生产库做恢复演练，不声称已完成生产恢复验证。

## 新年度日历

准备JSON，包含year、source以及days（该年每一天YYYY-MM-DD对应true/false开市状态），来源应为交易所已发布安排并核验：

```powershell
.\.venv\Scripts\python.exe -m quant.cli import-calendar calendar_2027.json
```

缺日期、非布尔值或缺来源会拒绝，不能直接按国务院调休推断证券市场开市。

## 主要接口

- POST /api/market-prepare：空对象仅更新；screen参数为选股方案；force=true强制新版本。
- GET /api/market-prepare[/{id}]：总体任务阶段、关联扫描与归档状态。
- POST /api/market-prepare/{id}/cancel：在安全边界停止。
- GET /api/multi-screens/history：limit、offset、day、state、scope分页检索。
- GET /api/multi-screens/plans：已有方案范围。
- GET /api/multi-screens/{id}?view=latest|archive&revision=N：最新财务或固定归档。
- GET /api/multi-screens/{id}/progress、/archives：轻量进度、归档修订。
- GET /api/multi-screens/{id}/export?format=csv|json&view=archive&revision=N：导出。
- POST /api/multi-screens/{id}/retry?workers=4：失败项新版本补算。
- POST /api/multi-screens/{id}/archive：补存归档或重试本地副本。

原直接选股API和MCP继续保留既有ID契约，可显式选择历史研究日期；网页入口固定走盘后准备流程。
